# Процесс сборки проекта CarRental - Подробное объяснение

## 🎯 Главный ответ: Сборка происходит через CMake, а IDE (VS Code) только запускает команды CMake

---

## 📋 Что такое CMake?

**CMake** - это система сборки (build system generator), которая:
- Читает файл `CMakeLists.txt` с описанием проекта
- Генерирует файлы для нативной системы сборки (Makefile для Linux, .sln для Windows)
- НЕ компилирует код сам, а создает инструкции для компилятора

**Аналогия:** CMake - это архитектор, который создает чертежи (Makefile), а компилятор (g++) - строитель, который по этим чертежам строит дом (исполняемый файл).

---

## 🔄 Полный процесс сборки (шаг за шагом)

### ШАГ 1: Конфигурация (CMake Configure)

**Что происходит:**
```bash
cmake -S /home/vladius/Desktop/apps/CarRENTAL -B /home/vladius/Desktop/apps/CarRENTAL/build
```

**CMake делает:**
1. Читает `CMakeLists.txt` из корня проекта
2. Ищет компилятор (g++), библиотеки Qt, другие зависимости
3. Сканирует все `.cpp` и `.h` файлы в папке `src/`
4. Создает файлы в папке `build/`:
   - `CMakeCache.txt` - кэш найденных библиотек и настроек
   - `Makefile` - инструкции для сборки
   - `compile_commands.json` - для автодополнения в IDE
   - `CMakeFiles/` - служебные файлы

**Когда выполняется:**
- Первый раз при сборке проекта
- При изменении `CMakeLists.txt`
- Вручную через задачу "CMake: Configure"

---

### ШАГ 2: Генерация Qt файлов (MOC, RCC, UIC)

**Что такое MOC/RCC/UIC:**
- **MOC** (Meta-Object Compiler) - генерирует `moc_*.cpp` файлы для Qt классов
- **RCC** (Resource Compiler) - компилирует `resources.qrc` в C++ код
- **UIC** (User Interface Compiler) - компилирует `.ui` файлы

**Где находятся:**
- `build/CarRental_autogen/` - все автогенерируемые файлы
- Например: `moc_MainWindow.cpp`, `qrc_resources.cpp`

**Когда выполняется:**
- Автоматически при сборке (благодаря `CMAKE_AUTOMOC ON` в CMakeLists.txt)

---

### ШАГ 3: Компиляция (Compilation)

**Что происходит:**
```bash
cmake --build /home/vladius/Desktop/apps/CarRENTAL/build --parallel
```

**Это запускает:**
```bash
make -j$(nproc)  # или gmake на некоторых системах
```

**Компилятор (g++) делает:**
1. Берет каждый `.cpp` файл:
   - `src/main.cpp` → `build/CMakeFiles/CarRental.dir/src/main.cpp.o`
   - `src/MainWindow.cpp` → `build/CMakeFiles/CarRental.dir/src/MainWindow.cpp.o`
   - `build/CarRental_autogen/mocs_compilation.cpp` → `build/CMakeFiles/CarRental.dir/CarRental_autogen/mocs_compilation.cpp.o`
   - И так далее для всех файлов...

2. Для каждого файла:
   - Препроцессор обрабатывает `#include`, `#define`
   - Компилятор переводит C++ в машинный код (объектные файлы `.o`)
   - Создает `.d` файлы с зависимостями

**Параллельная сборка:**
- `--parallel` использует все ядра процессора
- Файлы компилируются одновременно (быстрее!)

---

### ШАГ 4: Линковка (Linking)

**Что происходит:**
После компиляции всех `.cpp` файлов в `.o` файлы:

1. **Линкер (ld)** собирает все вместе:
   - Все `.o` файлы проекта
   - Библиотеки Qt (`Qt6::Widgets`, `Qt6::Sql`)
   - Системные библиотеки

2. **Создает исполняемый файл:**
   - `build/bin/CarRental` - готовый к запуску файл

**Почему в `bin/`:**
- В `CMakeLists.txt` указано: `RUNTIME_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/bin`

## 🖥️ Как VS Code интегрируется с CMake?

### Вариант 1: Сборка через задачи (Tasks)

**Файл:** `.vscode/tasks.json`

**Когда нажимаешь `Ctrl+Shift+B`:**
1. VS Code находит задачу "CMake: Build" (помечена как `"isDefault": true`)
2. Выполняет команду:
   ```bash
   cmake --build /home/vladius/Desktop/apps/CarRENTAL/build --parallel
   ```
3. Показывает вывод в терминале VS Code
4. Если есть ошибки - подсвечивает их в коде

**Зависимости:**
- Задача "CMake: Build" зависит от "CMake: Configure"
- Если `build/` пустая, сначала выполнится Configure

---

### Вариант 2: Запуск с отладкой (Launch)

**Файл:** `.vscode/launch.json`

**Когда нажимаешь `F5`:**
1. VS Code видит `"preLaunchTask": "CMake: Build"` в конфигурации
2. **Сначала** запускает задачу "CMake: Build" (собирает проект)
3. **Потом** запускает отладчик (gdb):
   ```bash
   gdb /home/vladius/Desktop/apps/CarRENTAL/build/bin/CarRental
   ```
4. Запускает программу с возможностью ставить breakpoints

**Параметры запуска:**
- `"program"` - путь к исполняемому файлу
- `"cwd"` - рабочая директория (откуда запускается)
- `"args"` - аргументы командной строки (пусто)

## 🔍 Что происходит при изменении кода?

### Инкрементальная сборка (Incremental Build)

**Если изменил `MainWindow.cpp`:**
1. CMake видит, что изменился только один файл
2. Компилирует только `MainWindow.cpp` → `MainWindow.cpp.o`
3. Перелинковывает все `.o` файлы в новый `CarRental`
4. **НЕ перекомпилирует** остальные файлы (быстро!)

**Если изменил `MainWindow.h`:**
1. CMake проверяет зависимости (через `.d` файлы)
2. Находит все `.cpp`, которые `#include "MainWindow.h"`
3. Перекомпилирует только их
4. Перелинковывает

**Если изменил `CMakeLists.txt`:**
1. Нужна полная переконфигурация
2. CMake перегенерирует `Makefile`
3. Может потребоваться пересборка всех файлов

## 🛠️ Команды вручную (без IDE)

### Полная сборка с нуля:
```bash
cd /home/vladius/Desktop/apps/CarRENTAL
rm -rf build
mkdir build
cd build
cmake ..                    # Конфигурация
cmake --build .             # Сборка
./bin/CarRental             # Запуск
```

### Быстрая пересборка:
```bash
cd build
cmake --build .             # Только сборка (конфигурация уже есть)
```

### Очистка:
```bash
cd build
cmake --build . --target clean  # Удаляет .o файлы, но оставляет конфигурацию
```

## 🎯 Итоговая схема

```
Исходный код (.cpp, .h)
         ↓
    CMakeLists.txt  ← Описание проекта
         ↓
    cmake -S . -B build  ← Конфигурация
         ↓
    Makefile + CMakeCache.txt  ← Сгенерированные файлы
         ↓
    cmake --build build  ← Сборка
         ↓
    Компилятор (g++)  ← Компиляция каждого .cpp
         ↓
    Объектные файлы (.o)  ← Промежуточные файлы
         ↓
    Линкер (ld)  ← Сборка всего вместе
         ↓
    build/bin/CarRental  ← ИСПОЛНЯЕМЫЙ ФАЙЛ ✅
```

---

## 💡 Ключевые моменты

1. **CMake НЕ компилирует** - он только создает инструкции (Makefile)
2. **Компилятор (g++) компилирует** - переводит C++ в машинный код
3. **Линкер (ld) собирает** - объединяет все в один исполняемый файл
4. **IDE (VS Code) только запускает** - выполняет команды CMake за вас
5. **Qt MOC/RCC** - автоматически генерируются перед компиляцией

## 🔧 Настройки в вашем проекте

**CMakeLists.txt:**
- Ищет Qt6 или Qt5
- Включает все `.cpp` и `.h` из `src/`
- Включает ресурсы из `resources.qrc`
- Собирает исполняемый файл `CarRental`

**tasks.json:**
- "CMake: Configure" - конфигурация проекта
- "CMake: Build" - сборка (по умолчанию при Ctrl+Shift+B)

**launch.json:**
- "C++: Launch CarRental" - запуск с отладкой (F5)
- Автоматически собирает перед запуском

## ❓ Частые вопросы

**Q: Можно ли собрать без IDE?**
A: Да! Просто выполни `cmake --build build` в терминале.

**Q: Что если удалить папку build?**
A: Ничего страшного. Просто выполни `cmake -S . -B build` заново.

**Q: Почему первая сборка долгая?**
A: Компилируются все файлы. Последующие сборки быстрее (только измененные файлы).

**Q: Что такое compile_commands.json?**
A: Файл для IDE, чтобы понимать, как компилируется проект (для автодополнения).

**Q: Можно ли использовать другой компилятор?**
A: Да, через CMake: `cmake -DCMAKE_CXX_COMPILER=clang++ ..`
