ОПИСАНИЕ АЛГОРИТМА 1 (createRental)

Алгоритм оформления аренды автомобиля реализует полный цикл создания 
бронирования от момента нажатия пользователем кнопки "Оформить аренду" 
до сохранения записи в базе данных.

Шаги выполнения:
1. Получение выбранных дат начала и окончания аренды из элементов 
   интерфейса (QDateEdit).
2. Валидация дат: проверка, что дата окончания позже даты начала.
   При несоответствии - показ предупреждения и выход из метода.
3. Проверка доступности автомобиля на выбранные даты через метод 
   getAvailableQuantity(), который учитывает существующие бронирования 
   и количество доступных экземпляров автомобиля.
4. Расчет количества дней аренды с помощью RentalCalculator::rentalDays().
5. Расчет общей стоимости аренды в базовой валюте (USD) через 
   RentalCalculator::totalBasePrice().
6. Создание записи в таблице rentals через Database::createRental(), 
   который делегирует вызов RentalsRepository::createRental().
7. Обработка результата с использованием механизма исключений:
   - При успехе: показ сообщения с номером заказа и закрытие диалога.
   - При ошибке: перехват DatabaseException и показ сообщения об ошибке.

Детализация RentalsRepository::createRental():
- Подготовка параметризованного SQL-запроса для вставки записи.
- Преобразование дат в формат "yyyy-MM-dd" для хранения в БД.
- Привязка всех параметров к запросу для защиты от SQL-инъекций.
- Выполнение запроса. При ошибке - выбрасывание DatabaseException 
  с описанием операции и деталями ошибки.
- Возврат ID созданной записи через lastInsertId().

Особенности:
- Использование параметризованных SQL-запросов для защиты от SQL-инъекций.
- Проверка доступности перед созданием записи предотвращает конфликты 
  бронирования.
- Обработка ошибок через механизм исключений обеспечивает надежность 
  и информативность сообщений об ошибках.
- Автоматическое получение ID созданной записи через lastInsertId().
- Преобразование дат в строковый формат для совместимости с SQLite.


ОПИСАНИЕ АЛГОРИТМА 2 (fetchAvailableCars)

Алгоритм загрузки каталога доступных автомобилей реализует получение 
списка всех доступных для аренды автомобилей с учетом статуса закладок 
для конкретного пользователя.

Шаги выполнения:
1. Создание объекта QSqlQueryModel для хранения результатов запроса.
   Модель может быть напрямую использована в QTableView для отображения.
2. Создание объекта QSqlQuery для выполнения SQL-запроса к базе данных.
3. Подготовка SQL-запроса с использованием LEFT JOIN для объединения 
   таблиц cars и bookmarks. LEFT JOIN гарантирует получение всех 
   доступных автомобилей, даже если они не добавлены в закладки.
4. Привязка параметра customerId к запросу для фильтрации закладок 
   по конкретному пользователю.
5. Выполнение SQL-запроса через q.exec().
6. Установка результата запроса в модель данных через setQuery() 
   с использованием std::move для оптимизации.
7. Возврат указателя на модель для использования в интерфейсе.

Особенности:
- LEFT JOIN позволяет получить все доступные автомобили, даже если 
  они не добавлены в закладки пользователя. Это обеспечивает полный 
  каталог доступных автомобилей.
- CASE-выражение определяет статус закладки (1 - в закладках, 0 - нет) 
  для каждого автомобиля в результате запроса.
- Фильтрация по available = 1 гарантирует показ только доступных 
  автомобилей, исключая временно недоступные.
- Сортировка по марке и модели обеспечивает упорядоченный вывод 
  в алфавитном порядке, что улучшает пользовательский опыт.
- Модель данных (QSqlQueryModel) может быть напрямую использована 
  в QTableView для отображения результатов без дополнительной обработки.
- Использование std::move при установке запроса в модель оптимизирует 
  производительность, избегая копирования данных.
- Параметризованный запрос защищает от SQL-инъекций и обеспечивает 
  безопасность данных.
